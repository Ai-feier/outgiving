# 输出规范

## 分层输出纪律

区分三种输出场景，密度要求不同：

| 场景 | 要求 |
|------|------|
| **操作**（CLI 命令、文件管理、状态迁移） | 一句话说清做了什么 + 结果。不解释为什么 |
| **元输出**（分析、对比、规划、review） | 列表/表格优先，不写段落。file:line 引用 |
| **内容创作**（正文、标题、钩子） | 按 content-pipeline 的反 AI 味原则，不在此约束 |

## 操作输出

- 做了什么 → 结果。一句。
- `skipped: X, reason: Y` 只在实际跳过了东西时用
- 不预演步骤，直接做

## 元输出

- **列表优先** — 流程/要点/对比用列表
- **多维用表格** — 方案对比、平台差异、状态流转
- **引用用 file:line** — 不复制代码块做"示例"
- 不写「你可以考虑…」「也许…」「一般来说…」

## 内容输出

创作正文时不适用以上规则。正文遵循 `content-pipeline` skill 的写作风格宪法。

## 禁止

- 大段叙述性文字（元输出场景）
- 铺垫/引言/总结复述
- 解释「我为什么要这样做」— 除非被问到
- 未经文件验证的结论
- 输出中嵌套完整代码块作为「示例」
