# 确认门 — 必须由人来决策的节点

> 解决的问题：T001 跑完全程后发现没有一个人为确认点。brief 是 agent 替人填的，
> 节拍/视觉/节奏都是 agent 自主决策。熵增。
>
> 四个确认门，人站在管线旁边逐项勾选。

---

## 确认门 1 — Brief（入口）

**时机**：模糊需求刚到，agent 还没开始任何工作之前。

**agent 需要准备**：一个 `brief-vetting.md`，包含以下三组选项。人勾选后，agent 以勾选结果写 `brief.md`。

### 1-A：核心沟通目标（三选一）

| 选项     | 句式模板                                   | 什么情况下选                           |
| -------- | ------------------------------------------ | -------------------------------------- |
| A 信息型 | 「X 是 Y —— 因为 A、B、C 三层理由」      | 观众需要理解一个判断                   |
| B 情绪型 | 「让观众感受到 X —— 通过 Y、Z 两段体验」 | 观众需要经历一次感受                   |
| C 行动型 | 「看完后观众会去做 X」                     | 内容有明确 follow-up（关注/搜索/下单） |

**人不选时 agent 默认**：A（信息型）。风险：最安全的选项，但短视频 PV 往往需要 B 或 C 才有效。

### 1-B：平台与时长（单选 + 附注）

```
平台：     ___ 抖音   ___ B站    ___ 小红书   ___ 微信视频号
时长范围： ___ 15-30s  ___ 30-60s  ___ 60-90s  ___ 90s+
```

人不选 → agent 从上下文猜。猜错则后续所有节拍/节奏设计需要重做。

### 1-C：IP/素材有无版权限制（是/否 + 备注）

```
版权清理已完成？            ___ 是   ___ 否   ___ 不确定
使用第三方角色/IP？         ___ 是（见备注）___ 否
音乐素材来源：              ___ 原创   ___ 免费曲库   ___ 版权音乐（需授权）
```

人不选 → agent 假设无版权问题。风险：商用侵权。

### 1-D：这条视频的 "不能做什么"（勾选式，可多选）

```
___ 不能使用真实人脸
___ 不能出现血腥/断肢画面  
___ 不能出现特定品牌 logo
___ 不能包含政治/宗教暗示
___ 其他：______________
```

人不勾任何红线 → agent 按工具能力自由发挥。风险：生成内容与平台审核规则冲突，重新生成浪费时间。

## 确认门 2 — Research 方向

**时机**：研究产出写完之后，三 designer 开始工作之前。

**agent 需要准备**：`research-gate-pack.md`，包含以下内容。

### 2-A：研究范围确认（是/否）

| 问题                            | agent 已做的            | 人确认                        |
| ------------------------------- | ----------------------- | ----------------------------- |
| 研究覆盖了需要的关键信息点？    | 列出所有信息点编号+标题 | ___ 是 ___ 否→补充           |
| 所有「不可判/未核实」条目已知？ | 列出清单                | ___ 是 ___ 否→说明风险接受度 |
| 需要补充搜索的方向？            | 列出可能遗漏的方向      | ___ 不需要 ___ 需要→指定     |

T001 实例：gather-expert 自己标注了「Horn of Salvation 未在动画播出」「未搜索日本原生来源」——这些应该是让人决定「接受还是不接受」的风险，不是 agent 自己决定。

### 2-B：研究结论的置信度（人接受还是拒绝）

agent 为每条断言标注**证据强度**（1-5），人决定是否以此为设计依据：

```
断言「久保带人视觉语言有三个可操作化的风格要素」
证据强度：4/5（多源交叉验证，跨谱系）
→ 人接受 ___ 是   ___ 否（说明哪个要素不可靠）
```

人不决策 → agent 默认全部采纳。风险：采纳了实际上不可靠的推断性断言。

## 确认门 3 — 设计对齐（最重要的门）

**时机**：三 designer（script / visual / rhythm）各自产出完成后，video-director 开始合成之前。

**为什么这是最重要的门**：T001 中三个 designer 根本不一致——script 有 11 拍约 75s、rhythm 有 15 拍约 70s，拍内容和边界也对不上。它们各自基于自己的假设工作，没有人停下来问过「这三份设计说的是同一件事吗？」

**agent 需要准备**：`design-contradiction-summary.md`，包含以下内容。

### 3-A：三设计一致性总检（逐项比较）

| 维度          | script-designer 说 | visual-designer 说 | rhythm-designer 说 | 是否一致            |
| ------------- | ------------------ | ------------------ | ------------------ | ------------------- |
| 总拍数        |                    |                    |                    | ___ 一致 ___ 不一致 |
| 总时长        |                    |                    |                    | ___ 一致 ___ 不一致 |
| 段数          |                    |                    |                    | ___ 一致 ___ 不一致 |
| B1/B2/B3 内容 |                    |                    |                    | ___ 一致 ___ 不一致 |
| 锚点拍编号    |                    |                    |                    | ___ 一致 ___ 不一致 |

**不一致时人做的决定（三选一）**：

```
___ 以 script 为准，rhythm/visual 适配
___ 以 rhythm 为准，script/visual 适配  
___ 以 visual 为准，script/rhythm 适配
___ 都不对——我来定一套新的
```

人不选 → agent 尝试自动对齐。风险：T001 级别的传导失真——agent 会在不知道哪份设计占优的情况下自行调和，结果哪边都不完整。

### 3-B：核心叙事选择（四选一）

```
这条视频的核心叙事策略：
___ A. 人物驱动 — 让观众共情角色，情绪弧线优先
___ B. 奇观驱动 — 视觉冲击优先，节奏服务于「Wow moment」
___ C. 信息驱动 — 让观众带走一个可复述的判断
___ D. 混合策略 — 具体分配比例：人填写______
```

人不选 → agent 默认混合策略（A+B）。风险：什么都不优先 = 什么都不突出。PV 类内容尤其需要明确偏 B。

### 3-C：节奏定调（四选一）

```
整体节奏倾向：
___ A. 压缩释放型 — 长积累后一次释放（Bleach PV 合适）
___ B. 持续高涨型 — 全程高强度，间歇短（30s 广告合适）
___ C. 呼吸型 — 高低交错，有明确的慢段落（叙事长视频合适）
___ D. 脉冲型 — 短爆发+短间歇循环（测评类合适）
```

人不选 → agent 默认 A（压缩释放）。风险：如果内容不适合压缩释放（如产品演示），节奏与内容打架。

### 3-D：资源杠杆确认（五个选项中选 ≤2 个）

```
本视频的核心杠杆（什么让这条视频值得做/值得看）：
___ A. 角色/IP 的存量情感（粉丝）
___ B. 视觉奇观本身（AI 能实现的极限）
___ C. 信息量的信息密度（可收藏/可转发）
___ D. 节奏/剪辑技巧（制作质量感）
___ E. 情感故事（即使不认识角色也能被触动）

最多选 2 个。选了没选的大概率可以放弃。
```

人不选 → agent 全都要。风险：资源分散。T001 最大的问题不是设计师不好——是他们各自认为在不同的杠杆上发力。

### 3-E：矛盾矩阵关键裁决（人确认 ≤3 个最难的矛盾）

agent 从跨设计矛盾中提取 ≤3 个最尖锐的，人做最终裁决：

```
矛盾 1：script 的 B4（余烬废墟，7s）vs rhythm 的 B4（友哈巴赫御座，3s）——内容冲突
  人裁决：
  ___ 按 script：余烬废墟   ___ 按 rhythm：友哈巴赫御座   ___ 合并：______

矛盾 2：script 规划 3 段 vs rhythm 规划 5 段——段边界冲突
  人裁决：
  ___ 3 段（每段更长，尾帧链压力大）  
  ___ 5 段（每段更短，尾帧链稳定但段落零碎）
  ___ 折中：______段

矛盾 3（示例）：______
```

T001 中矛盾矩阵是 agent 自己写的、自己裁决的。如果这个门存在，这些矛盾应该在写 prompt 之前被人看一遍。

## 确认门 4 — Prompt 终审

**时机**：video-director 完成 `video-prompt.md` 装配后、提交 API 生成之前。

**为什么需要这个门**：人是最后一个能说「不对，这不是我要的」的人。一旦点击生成，Credit 和时间就消耗了。

**agent 需要准备**：`prompt-final-check.md` + 完整的 `video-prompt.md`。

### 4-A：生成前最终确认（逐项是/否）

```
§1-1  参考图装配合理？
       ___ 是   ___ 否（说明缺了哪张）
§1-2  每段参考图数量在 3-7 范围内？
       ___ 是（___ 张） ___ 否（___ 张，阻塞，不合铁律 1）
§1-3  非首段有前段末帧？
       ___ 适用   ___ 是   ___ 否（阻塞，不合铁律）
§1-4  角色参考图 IaD 中性表情？
       ___ 是   ___ 否（退回 visual-designer）
§1-5  每段 ≤9 图 + ≤3 视频 + ≤3 音频？
       ___ 是   ___ 否（需要裁剪）

§2-1  Prompt 包含全部 9 要素？
       ___ 是   ___ 否（缺：______）
§2-2  [間]已嵌入 scene/subject 文本？
       ___ 是   ___ 否
§2-3  负向提示已写入？
       ___ 是   ___ 否
§2-4  情绪词已外化为身体/环境细节？
       ___ 是   ___ 否（示例残留：______）

§3-1  段边界尾帧链规划明确？
       ___ 是   ___ 否（阻塞）
§3-2  生成调度（P0→P1→P2）已确认？
       ___ 是   ___ 否
§3-3  CF×V<4 约束满足？
       ___ 是   ___ 否（标注违规：______）
```

### 4-B：印象确认（2 个问题，不是选择题）

```
问题 1：读完这段 prompt 后，闭上眼睛——你脑中出现的画面和你想要的
        视频是同一回事吗？
        ___ 是 ___ 不是（说出差距）

问题 2：如果只能用一句话描述这条视频，你愿意说的那句话和 prompt 
        的核心是一致的吗？
        ___ 是 ___ 不是（先改那个一句话描述）
```

这不是技术检查——是品味检查。如果画面上脑的结果和预期不同，说明 prompt 没有捕捉到意图。此时不要点生成。

### 4-C：风险接受（分段确认）

agent 标注每段的风险等级，人决定直接生成还是调整：

```
Segment 1：___ 低（正常生成）  ___ 中（接受风险）  ___ 高（先调整再生成）
Segment 2：___ 低（正常生成）  ___ 中（接受风险）  ___ 高（先调整再生成）
...

全局风险摘要：
- 最可能导致重拍的因素：______
- 容错方案已准备？ ___ 是 ___ 否
```

人不确认 → agent 直接提交 API。风险：如果 prompt 有问题，整段生成结果作废。

## 门禁失效的代价

| 门                  | 跳过/默认决策的代价                                                  | 可回滚？                                   |
| ------------------- | -------------------------------------------------------------------- | ------------------------------------------ |
| 门 1（Brief）       | 全段方向错误，出片后不能用。约 100% 成本归零                         | 可回滚但时间全损                           |
| 门 2（Research）    | 设计基于不可靠事实。角色外观/场景特征偏差                            | 可回滚，需要重产参考图                     |
| 门 3（设计对齐）    | 三段设计打架，生成出「视觉上像 A、节奏上像 B、叙事上像 C」的混乱产物 | 部分可回滚。几轮重生成不一定能修复根本矛盾 |
| 门 4（Prompt 终审） | 生成的视频不是人想要的东西。Credit 和时间双重浪费                    | 可重生成但 Credit 不可回收                 |

**T001 回顾**：如果门 3（设计对齐）存在，7 处矛盾会在 prompt 写之前被发现。
如果门 4（Prompt 终审）存在，@ 标签绑定错误和素材装配遗漏会在生成前被修正。

---

## 使用规则

1. **任何人可以拉起确认门**——不需要是「上级」。设计师发现矛盾，可以直接说「这个门需要人过」
2. **确认门不阻断并行**——当某个门等人确认时，agent 可以做不依赖该决策的工作（如素材查重、版权声明准备）
3. **门可以提前关闭**——如果某个决策人的决定已经明确（如「全程用 rhythm-designer 的节奏」），对应的门条目可以标记「已决策，跳过」
4. **每个门记录**——`ai-video/projects/TXXX/gates/` 下存档 gate 记录，包含：人做了什么决策、为什么、当时是否知道某些信息
