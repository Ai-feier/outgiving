## 1. 产品定义

**一句话**：内容生产线 = 只增不改的 markdown **图**（DAG）；每个节点是一份**人能验收的契约**（goal 立标准 ⇔ end 交答卷）；agent 是工人，workbench 是控制面，人只做四件事：**改 ①、grill ②、过门、验收 end**。

| 维度 | 内容 |
| ---- | ---- |
| 核心对象 | 层（契约块）/ 单元（一次 AI 事务，5 层）/ 链（DAG，只增不改） |
| 用户 | 人（验收者，本机 127.0.0.1）· 主会话 agent（操作员）· 4 designer agent（工人） |
| 事实源 | md 文件。workbench 只读写 md，不建第二套存储 |
| 明确不做（v1） | 外部用户/多人协作 · 生成按钮（生成仍走 CLI/主会话）· 云端部署 · 编辑 diff 历史 |
| 原则 | agent 自主性第一（中间单元由 goal 动态规划）；md 单源；共享文件 = 共享内存；**链是图不是列表**（布局/边/标注全部按图语义，§4.1） |

## 2. 核心模型

### 2.1 单元 = 一次 AI 事务（5 层）

每单元一份 md。5 层按"谁写的、是什么"切分：

```markdown
---
unit: research        # 项目内唯一
层: l1                # 所属层
follows: [goal]       # 前置（可多个、可跨层指向任意单元；goal 无 follows）
gate: 是              # 可选。产出后人必须过目才放行下游（§2.6）
title: …             # 可选展示名
---
# H1 显示标题
> 状态: 就绪           # 五态之一（§2.7），缺省=未开始

## ① 简层
## ② 思考
## ③ 内容详情
## ④ 执行
## ⑤ 结果
```

| 层 | 定位 | 内容 |
| -- | ---- | ---- |
| ① 简层 | 人话主张 | 交付什么 + 关键参数，≤3 行，人可改（超行软校验黄标） |
| ② 思考 | 过程说明（**没有交付物**） | 分析问题、如何思考、用什么 skill/工具及为什么、决策+依据；固定小节 `### 假设与未锚`（无则写"无 + 一句理由"）+ `### grill 记录`（人追问，agent 下轮迭代前必读必答） |
| ③ 内容详情 | 交付物本身 | 设计单元 = 完整设计件；运行单元 = 完整提示词 + 参考图清单 + 关键参数（提示词正文单源在 `exec/*.md`，③ = `prompt-file:` 指针 + 关键参数，不内联全文） |
| ④ 执行 | 跑起来 | 执行元数据（`agent:`/`provider:`/`model:`/`skill:`/`refs:`）、前置清单、`### Run N` 卡；设计单元无执行则写「无 + 一句理由」（不凑字） |
| ⑤ 结果 | 事后交代 | 结果指标、`### 对齐自报`（逐项 🔴/🟡/✅ + 一句说明）、`### 交接`、门记录 |

**运行单元判定（数据驱动）**：④ 含 `prompt-file:` 或 Run 卡 = 运行单元，否则设计单元。

### 2.2 层级 = 契约

```
层 l1 = 1 goal + n 中间单元 + 1 end
```

- **goal 单元**（层始，恰好 1 个）：
  - ① = **验收标准**：逐行、可检查。全局红线写进相关层 goal ①，**继承必须显式**（下层 goal ① 写明"继承 L1 红线：…"）。
  - ② = 共同理解（六维表：一句话是什么/核心沟通目标/平台时长/风格/版权红线/生成策略）+ 分解理由 + 假设与未锚。
  - ③ = **单元计划**：计划单元表（unit | ① 草案 | agent | gate | 顺序）+ 派发说明。
  - ④ = 无。⑤ = 层放行门记录。
- **中间单元**（n 个，0 也可）：见 §2.1。类型是开放词表（research/script/visual/rhythm/director/segN 都是例子）。4 designer 是**可派发的 agent 能力**，不是固定管线位。
- **end 单元**（层末，恰好 1 个）：
  - ① = 一句话（本层产出如何回答 goal）。
  - ② = 验收分析（怎么核的证据、查了什么）。
  - ③ = 本层产出（交付物指针 + 关键指标 + 全链成本/耗时累计）。
  - ④ = 验证执行记录（`ai verify` 等，无则「无」）。
  - ⑤ = **验收表**（逐条 goal ① claim → 证据 → ✅/⚠️/❌；任一行 ❌ → 层失败，不交接）+ **交接块**（给下一层的输入）。

### 2.3 前置与层间关系

**前置是单一概念**：`follows` 即前置，可多个，**可跨层指向任意单元**（如 l2 的 goal2 `follows: [end-l1, seg1]`——同时消费层交接和 seg1 的末帧）。跨层消费的具体资产（末帧路径等）写进消费单元的 ③/④，不靠图边承载细节。

```
l1: goal → research → … → seg1 → end-l1
l2: goal2 (follows: [end-l1, seg1]) → seg2 → end
人看片不满 → l(k+1).goal（引用 lk 产出 + 写明修正）→ …
```

**层边界规则（机器可判）**：

- **goal 不变** → 原运行单元 ④ 内 `Run N+1` 重跑（append-only）。
- **goal 变** → 旧层 `superseded_by: l(k+1)`，开新层。不回改历史层文件。
- 层级只增。
- 全局红线/约束不算前置——仍走 goal ① 显式继承，不进图。

### 2.4 动态单元生成

- **规划**：goal ③ 单元计划。计划单元在图视图 = 虚线节点。
- **落地**：中间单元文件由**主会话**创建（frontmatter + ① 草案，agent 填 ②③④⑤）。中间单元可**提议**增删单元（写进自己 ②），只有主会话落地。
- **grill 分解决策**：人质疑"为什么切这几个单元"打在 goal 的 ② 上。

### 2.5 层规则（chain.py 可判）

- 层始 = goal：层内无前驱（同层单元不 follows 它），恰好 1 个；可持跨层 follows（指向上层任意单元）。
- 层末 = end：层内无后继，恰好 1 个。
- 跨层前置：不限制（D39）。层是**逻辑契约块**，不是拓扑切割。
- 违反"恰好 1"、层无 goal 或无 end → `layer_errors[]`（视图顶部告警条，不阻断渲染）。
- 全项目无 `层:` 字段 → 单个默认层 `default`；遗留 `段:` 字段只读兼容（不校验）。
- 层显示名 = goal H1。层状态（派生，不存储）：任一单元失败→失败；任一运行中→运行中；层末完成且全层无失败→完成；否则 进行中。

### 2.6 门（2 个机制）

1. **层边界审批**：下一层 goal ① 必须人放行（workbench goal 卡 [放行]），该层中间单元才允许开工。放行记录 = goal **⑤** 追加 `### 门 · 层放行 · …`。
2. **单元门**：frontmatter `gate: 是` = 本单元 ③ 产出后**停**，人过目（运行单元含装配请求体 + 成本视图），放行/打回；记录追加进该单元 **⑤** `### 门 · …`。

实例（按位置列举，不是锚定）：首层 goal ① 的层边界审批 · research 单元 `gate: 是`（研究方向）· 收口单元 `gate: 是`（设计对齐）· 每个运行单元 `gate: 是`（成本门：花钱前看请求体）。

门可以提前关闭（标"已决策，跳过"进 ⑤ 门记录）。任何人可拉起门（grill 目标单元 ②）。门不阻断不依赖该决策的并行工作。

### 2.7 状态

五态：`未开始 | 就绪 | 运行中 | 完成 | 失败`。位置：H1 下一行（允许隔 1 空行）`> 状态: <态>`；全/半角冒号皆可；缺省=未开始；非法值按未开始显示并提示原值。agent 写单元文件时同步写状态行（内容就绪→就绪；发起生成→运行中；Run 卡写入且成功→完成；失败→失败）。人经视图卡顶 5 态下拉改写（同一行，md 为准；409 防并发覆盖）。

### 2.8 人的触点（4 动作）

| 动作 | 落点 | 语义 |
| ---- | ---- | ---- |
| 改 ① | 任何单元 ①（写回 md） | 改主张。agent 下轮迭代前必读 |
| grill ② | 任何单元 ② `### grill 记录`（append） | 问推理。agent 必读必答 |
| 过门 | goal ⑤ 层放行 / gate 单元 ⑤ 门记录 | 审批（含运行单元请求体终审） |
| 验收 end | end ⑤ 验收表 + 交接块 | 层完成确认；打回 → 层内重跑或改 goal 开新层 |

对齐自报在各设计单元 **⑤**（回读其他单元 ③ 后逐项标注 🔴/🟡/✅；🔴 未关闭 → grill 对方 ② 或触发收口单元门，人裁决）。跨单元意见 = grill 所指产出的那个单元 ②；层级/方向意见 = 写进下一层 goal ① 草案。

## 3. 写作规格（agent / 主会话读，唯一规格）

### 3.1 frontmatter

```yaml
unit: <项目内唯一 id>
层: <l1|l2|…>            # 缺省 → default 层
follows: [<前置 unit id>, …]  # goal 为空/缺省；可跨层
gate: 是                  # 可选
superseded_by: <l(k+1)>   # 可选，层被替代时
title: <展示名>            # 可选
```

元数据键名不含 `/`（解析器限制）：`provider`/`model` 拆两个 key。

### 3.2 goal 单元

- ① 验收标准：每行一条可检查 claim。全局红线在此显式列出。
- ② 共同理解表（六维 + 四方确认）+ 分解理由 + 假设与未锚 + grill 记录。
- ③ 单元计划：

```markdown
## ③
- 计划单元：
  | unit | ① 草案 | agent | gate | 顺序 |
  | ---- | ------ | ----- | ---- | ---- |
  | research | 找 2 张权威参考图 + 官方形态描述 | gather-expert | 是 | 1 |
  | script | … | script-designer | 否 | 2 |
- 派单：主会话直接做 research → designer 并行（script 先广播方向）→ 收口 → 门
```

- ④ 无。⑤ 层放行门记录（人放行后填）。

### 3.3 中间单元

- ① ≤3 行，**禁止纯指针**（① 必须自明；细节在 ②③）。
- ② 分析问题 + 如何思考 + 用什么 skill 及为什么 + 决策与依据 + `### 假设与未锚` + `### grill 记录`（格式 `- {YYYY-MM-DD HH:MM} · user\n  {text}`，agent 回答缩进跟后）。**思考里没有交付物。**
- ③ 设计单元 = 完整设计件（节拍/宪法/曲线…）；运行单元 = `- prompt-file: exec/…` + 完整提示词关键参数 + `- refs:` 参考图清单。
- ④ 运行单元：执行元数据 + 前置清单（GFM `- [ ] dry-run` / `- [ ] refs 可解析` / `- [ ] 成本 ≤¥x`）+ Run 卡。设计单元：「无（设计单元，无生成执行）」或 skill 调用记录。
- ⑤ 结果指标 + `### 对齐自报`（逐项 🔴/🟡/✅）+ `### 交接`。

### 3.4 end 单元

- ① 一句话。② 验收分析。③ 本层产出（指针 + 指标 + 全链成本/耗时）。④ 验证记录（无则「无」）。
- ⑤ 验收表（必填，逐条 goal ①）：

```markdown
### 验收表（对 goal ① 逐条）
| goal ① claim | 证据 | 状态 |
| ------------ | ---- | ---- |
| 出 seg1 A/B 两版 | Run 1 (H3) + Run 2 (Seedance)，outputs/… | ✅ |
| 末帧可作接续锚 | 末帧 YAVG 51.65 + 形态完整（对照 001/002 待目验） | ⚠️ |
```

  状态 ∈ ✅/⚠️（有保留，写明）/❌（不通过，层失败，不交接）。+ 交接块（`- 交接 → L2 goal: <交付物指针 + 状态描述 + 预算>`）。

### 3.5 Run 卡（运行单元 ④ 内）

`### Run N · provider · 日期 · 成功/失败` + kv（时长/分辨率/成本/耗时/task id）+ 一句话结果 + 可选详情 + 产出指针。Run# = ④ 内 `^###\s+Run\s+(\d+)` 最大编号 + 1（服务端算，人不手写编号）。只追加不重写。

### 3.6 门记录（goal ⑤ / gate 单元 ⑤ 内）

`### 门 · {层放行|单元门} · {日期} · {批准|打回|已决策跳过} · {一句话理由}`。

### 3.7 状态行 / 409 / 幂等

同 §2.7。写回带 `expected_body` 逐字校验（变了 → 409）；append 类操作幂等键 60s 窗口 + per-file `threading.Lock`。

## 4. 人的工作面（workbench 控制面）

### 4.1 视图 — 图设计（DAG，不是列表）

默认 = 层块（拓扑序），块内 = **真 DAG**。生产链本质是有向图；布局、边、标注全部按图语义，不做成线性列表。

- **布局**：拓扑列布局（列号 = 拓扑深度，从层始最长路径起算），同列纵向堆叠。多前置 = 多条收敛边，各带箭头——分叉/收敛自然可见。
- **边**：所有 `follows` 边全绘制；跨列边画曲线，不吞边。
- **跨层前置**：与层内边不同色 + 端点标单元名；层块 hover 高亮所有进出的跨层边。
- **纯链压缩**：仅当每节点恰好 1 前置 1 后继（DAG 退化为路径）才压成紧凑单行；有分叉/收敛一律全 DAG。
- **计划单元**：虚线节点。
- **前置只上图与侧栏**，不进卡头（卡头 ≤5 元素，§4.8）。

单元卡：

```
┌ L1 · 出 seg1 A/B ── 进行中 · 验收 2✅1⚠️0❌ · goal [已放行] ┐
│  DAG：goal → research → script ─┬→ visual ─┐
│                    └────────────→ rhythm ─┼→ director → seg1(⟳)
│  每个节点 = 单元卡：① 常显可改；②③④⑤ 折叠单行摘要        │
│  end：⑤ 验收表常显 · 交接块常显                           │
└──────────────────────────────────────────┘
        ↕ 交接箭头（标注：待审批 L2 goal）
```

- 运行单元 ④：「看请求体」（装配真实 API 请求体 + 成本 + 命令，等价 --dry-run）、前置清单可点勾、「记录运行」表单（必填仅成败 + 一句话）。
- gate 单元 ⑤：[批准] [打回]。
- 媒体：`[文本](outputs/x.mp4)` / 图片自动内联可播；缺媒体 → onerror 占位。
- 告警条：`layer_errors` / 缺 follows / 非法状态值。
- 文件视图（📄）保留：原始 md 块编辑；prompt 文件独立可编辑。
- UX 契约（命令条/侧栏/状态矩阵/写回与门/视觉/a11y/视口）：§4.4–4.10。

### 4.2 四个入口（对应 §2.8）

改 ①（写回）· grill ②（append）· 过门（goal ⑤ 放行 / gate 单元 ⑤ 批准打回）· 验收 end（验收表确认 → 层完成 + 下层 goal 解锁；打回 → 意见进 goal ② 或开新层）。

### 4.3 门内容参考（审批时展开对照）

- **层边界审批（首层 goal）**：核心沟通目标（信息/情绪/行动）· 平台 + 时长 · 版权红线 · "不能做什么"清单。人不选 → agent 默认信息型 + 无版权假设。
- **research 门**：研究覆盖关键信息点？· 不可判条目已知且接受？· 每条断言证据强度（1-5）。
- **收口门**：各设计单元 ⑤ 对齐自报一致性总检（总拍数/总时长/段数/锚点拍，逐项；不一致 → 以谁为准 三选一 或 人定新）· 核心叙事策略 · 节奏定调 · 资源杠杆 ≤2 · 最尖锐矛盾 ≤3 条人裁决。
- **运行门（成本门）**：请求体装配检查（参考图数量/首末帧/9 要素/负向/尾帧链）· 品味检查 2 问 · 分段风险接受（低/中/高）。不确认 → 不生成。

**门禁失效的代价（T001 实测）**：首层门跳过 ≈ 100% 成本归零；收口门跳过 = 视觉像 A、节奏像 B、叙事像 C 的混乱产物。门可以跳过，代价表必须看。

### 4.4 命令条与当前位置

- **命令条**（视图顶部 sticky）：当前阻塞点（第一个未完成层 → 其中第一个可行动单元）+ 下一动作 + 主按钮。gate 单元 → [批准][打回][改①]；运行单元 → [看请求体][记录运行]；设计单元 → [改①][追问]。
- **默认选中 = 第一个可行动单元**。载入自动滚到当前层。

### 4.5 侧栏 = unit inspector（按单元类型契约）

- **设计单元**：② 结论摘要 + 未解决 grill 数 + 前置/后继（点击跳转）+ 动作。
- **运行单元（exec panel，一个闭环）**：前置清单 n/m + 成本 + 请求体 + 命令 + [记录运行]；装配失败 → 禁用记录。
- **gate 单元**：[批准] [打回] + §4.3 门参考（展开对照）+ 代价表。
- **end 单元**：验收表（表格渲染，逐行可点）+ 交接块 + [验收] [打回]。
- **metadata** 降为折叠单行，非空才显示。

### 4.6 状态矩阵

| 状态 | 呈现 |
| ---- | ---- |
| 加载 | 层块骨架 + "加载链…" |
| 空 | nochain 文案（提示 agent 建立生产链的落点） |
| 错误 | 顶部告警条，覆盖 `layer_errors` / `missing` / 非法状态值 |
| stale | 409 → 对话框"这一层在你填写期间被改过（md 为准）"+ [刷新后重试] |
| 刷新 | header [⟳] + 15s 轮询（`document.hasFocus()`）+ 命令条最后更新时间 |
| 持久化 | sessionStorage：project / 选中 / 层折叠 / 滚动位置 |

### 4.7 写回与门体验

- **按钮权重**：primary = accent 填充；secondary = 中性 outline。
- **改状态**（5 态下拉）：无确认 + flash；重处理由 agent 触发。
- **门**：打回必填一句话 → 意见进下层 goal ② 草案；批准 → 门记录进 ⑤。
- **动作后行为**：记录运行 → 滚动到新 Run 卡 + 高亮；grill → ② 展开定位新记录。

### 4.8 视觉契约

- **颜色语义**：`--acc` 橙 = primary action + 品牌，专属；**failed = 红色保留**；**选中 = 中性亮色 outline**；跨层前置边 = 与层内边区分的独立色（非 accent 非红）。
- **卡头 ≤5 元素**：状态点 / unit / 标题 / agent 徽标 / 状态下拉；前置不进卡头；卡头不换行。
- **折叠 ②③④⑤ 必须单行摘要**：② = 最后结论 + 未解决 grill 数；③ = 交付指针/提示词文件 + 参考图数；④ = 清单 n/m + Run 数 + 最新 Run 状态；⑤ = 验收/指标摘要。
- **排字**：UI = system 栈；数据/JSON = ui-monospace + `tabular-nums`；字号 floor 11px。
- **图**：边箭头指向目标节点（marker 按层 id 命名防冲突）；拓扑列布局不得强制单行；纯链压缩规则见 §4.1。

### 4.9 a11y floor（硬契约）

- SVG 节点 / 单元头 / 层头：`tabindex=0` + `role=button` + Enter/Space 激活。
- 模态：`role=dialog` + `aria-modal` + 全局 Esc；关闭后 focus 回触发元素；打开时 focus 首个输入。
- flash / 409 对话框：`aria-live=polite`；状态下拉有可见 label。
- 全量 DOMPurify：动态 HTML 唯一出口 `setHTML()`。

### 4.10 视口契约

- 最小宽度 **1100px**（本机桌面工具；更窄 → 提示加宽）。
- 侧栏可折叠至 0；DAG 横向滚动（不缩放节点）。

## 5. 技术栈与 API

**技术栈（零新依赖）**：Python stdlib `ThreadingHTTPServer`；`scripts/src/workbench/{server,chain,mdblocks,assemble}.py`；前端 `app.html` 单页 + vendor OSS；绑定 `127.0.0.1:8766`。

| 路由 | 说明 |
| ---- | ---- |
| `GET /api/chain` | `{order, missing, layer_errors[], layers:[{id,title,units,start,end,state}], units:[{unit,title,层,follows,gate,state,exec_kind,planned,parts:{claim,thinking,content,exec,result},meta}]}` |
| `POST /api/chain/part` | `{p,unit,part,expected_body,new_body}` 写回 5 层之一（stale → 409） |

**chain.py 解析**：5 节（`## ① 简层` / `## ② 思考` / `## ③ 内容详情` / `## ④ 执行` / `## ⑤ 结果`，编号必须，后缀可省）；旧 4 节文件（`## ③ 执行` / `## end 结果`）只读兼容映射 + 警告。`exec_kind`：④ 含 `prompt-file:` 或 Run 卡 → run。层规则按 §2.5（跨层前置不校验）。
