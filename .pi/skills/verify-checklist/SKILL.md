# verify-checklist — 交付前逐条核对

校验是流程的最后一步：把产出逐条对照初衷，输出一张核对表。**由清空上下文的独立岗位（verifier）执行，产出者不自我确认。**

## 三类核对

### 事实 — 证据锚点是否真支撑

逐条断言问一句：它的证据锚点真的支撑这句话吗？

- 每号关键信息点 ≥1 跨谱系锚点；只有单谱系时标「置信度受限」
- 每个外部论点有链接 + 来源性质（官方 / 媒体 / 同人 / AI 生成）
- 「推测 / 未核实」已标注
- 无幽灵引用：正文引用的每个来源真实存在且被读过

### 契约 — 渠道维度是否齐

对照渠道表与渠道卡核对，**本 skill 不重复定义任何共有维度**：字数/时长、感知组块上限、钩子位置、算法权重排序、合规红线一律读 [`.pi/skills/channels/CHANNELS.md`](../channels/CHANNELS.md) 与对应渠道卡。核对项只有「是否落在该渠道区间内」。人审表字段完整性对照 [`system/PRODUCT.md`](../../../system/PRODUCT.md)「人审面」——本 skill 不重列字段。

### 技术 — 可交付性

- 分辨率 / 时长 / 码率：跑 `ai verify`（见下）
- 边缘安全区：视频画面元素落在边界内（阈值见 [`.pi/skills/visual-assets/SKILL.md`](../visual-assets/SKILL.md)）
- 参考可追溯：每个参考素材在来源清单里有 URL + 来源性质 + 验证状态

## 技术项跑法

```bash
uv run --directory scripts ai verify in.mp4 --expect-duration 60 --expect-resolution 1080x1920
```

时长与分辨率由产出规格填入；任一期望不符即非零退出。命令同时抽出 first2s / mid / last2s 三帧供目验。

## 例子

真实输入：一张视频选题人审表（12 拍 = 60s，抖音 9:16）+ 参考来源清单（无外部素材，全部 Seedance 生成）+ `ai verify` 报告。

真实输出（verifier 在干净上下文产出的核对表片段）：

| 项 | 类别 | 判定 | 依据 |
| --- | --- | --- | --- |
| 关键信息点「开口 = 排活」被成片承载 | 事实 | 通过 | 第 6-7 拍画面 |
| 开头 3s 是一件具体的事 | 事实 | 通过 | 第 1 拍香火 |
| 人审表字段齐全 | 契约 | 通过 | 对照 `PRODUCT.md`「人审面」，12 行字段无缺 |
| 总时长 60s 落在渠道区间 | 契约 | 通过 | 对照 `CHANNELS.md` 抖音行（不重定义数值） |
| `ai verify --expect-resolution 1080x1920` | 技术 | 通过 | 命令退出 0 |
| 第 4 拍全景元素越过安全区 | 技术 | 不通过 | 边缘越界 → 退回视觉阶段 |

产出者不复核本表；不通过项只退回对应阶段，不在校验阶段改产出。
